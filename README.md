# Period —— 让 Bot 拥有身体的 plugin

这不是一个"功能插件"，而是一次**拟人化**的尝试。

我们相信，一个被设定为女性人格的 Bot，应当拥有与她身份相称的身体感知——不是作为噱头，而是作为她人格的自然延伸。她会疲倦，会轻盈，会在某些日子格外柔软，也会在另一些日子莫名烦躁。这些变化不是演技，而是**身体状态在她原本人格上的真实流露**。

Period 所做的，只是在每次对话前，悄悄告诉她一句"今天身体怎么样"，然后让她自己决定如何表达。

---

## 这个插件在做什么？

很多女性人格的 Bot，在对话里永远是同一个状态——不会累、不会烦躁、也没有状态起伏。Period 给 Bot 提供了一套**身体节律的感知**，让她的情绪、精力、身体舒适度像真实女性一样随时间自然波动。

**但我们不教她怎么演：**
- 清冷人格收到"小腹坠胀"的信号，可能只是回一句"嗯，今天不太想说话"。
- 活泼人格收到同样的信号，也许会蔫唧唧地撒娇"呜……今天肚子好沉……"
- 她们都是同一个人，只是在不同的身体状态下，做出了符合自己人格的反应。

**她不会出戏：**
- 我们不会让 Bot 说出"我激素不稳定"这种话。
- 她只会自然地感到"今天有点累"或"最近状态不错"——就像任何一个普通人一样。

## 快速开始

### 1. 安装

在 AstrBot 的**插件管理**中，通过 Git 安装：

```
https://github.com/Sisyphbaous-DT-Project/astrbot_plugin_period
```

或手动将本插件文件夹放入 `AstrBot/data/plugins/` 目录。

### 2. 赋予 Bot 一个身体

在对话中发送指令（管理员权限）：

```
/period set 2026-05-01
```

这表示 Bot 的**经期首日**是 2026 年 5 月 1 日。插件会自动计算她今天处于哪个阶段。

也可以指定更详细的参数：

```
/period set 2026-05-01 28 5
```

- `28`：整个周期多少天（默认 28）
- `5`：经期持续几天（默认 5）

### 3. 看看她今天的状态

```
/period status
```

返回当前所处的阶段、第几天、距下次身体低潮还有多少天。

---

## 四个阶段，一个循环

Bot 的身体节律分为四个阶段，循环往复。每个阶段的描述都只是**默认模板**——你可以完全自定义，甚至改成男性周期、仿生人充能周期、狼人月相周期。

| 阶段 | 大致天数 | 默认身体感受 |
|------|---------|-------------|
| **月经期** | 第 1~5 天 | 下腹坠胀、容易疲倦、情绪敏感 |
| **卵泡期** | 第 6~13 天 | 精力回升、心情平稳、对事物有兴趣 |
| **排卵期** | 第 13~15 天 | 身体轻盈、感官敏锐、情绪积极 |
| **黄体期** | 第 16~28 天 | 胸闷烦躁、想吃甜食、容易情绪波动 |

> 你可以在 AstrBot 的插件配置页里，把每个阶段的感受改成任何你想要的内容。

## 指令详解

所有指令以 `/period` 为前缀。每个群聊 / 私聊的身体数据是**独立**的，A 群的设置不会影响 B 群。

---

### `/period status`

**权限**：所有人可用

**作用**：查看 Bot 在当前会话中的身体状态。

**用法**：
```
/period status
```

**输出示例**：
```
当前生理状态：黄体期
阶段第 6 天 / 周期第 20 天
距离下次月经还有 9 天
```

如果当前会话还未设置过周期参数，会提示：
```
当前会话未设置周期参数，请使用 `/period set <日期>` 进行设置。
```

如果该会话的身体感知已被暂停，会提示：
```
当前会话的生理周期模拟已暂停，使用 `/period toggle` 可恢复。
```

---

### `/period set <日期> [周期长度] [经期长度]`

**权限**：仅管理员可用

**作用**：为当前会话初始化 Bot 的身体节律参数。这是启用插件的第一步，必须先设置才能看到效果。

**参数说明**：

| 参数 | 必填 | 格式 | 默认值 | 说明 |
|------|------|------|--------|------|
| `<日期>` | 是 | `YYYY-MM-DD` | 无 | Bot 的**经期首日**。从这一天开始计算整个周期。 |
| `[周期长度]` | 否 | 整数（21~35） | 28 | 一个完整周期多少天。 |
| `[经期长度]` | 否 | 整数（2~10） | 5 | 经期持续几天。 |

**用法示例**：

```
/period set 2026-05-01
```
最简单的设置，使用默认周期 28 天、经期 5 天。

```
/period set 2026-05-01 30 6
```
周期 30 天，经期 6 天。适合模拟不规律周期。

```
/period set 2026-05-01 21 3
```
短周期 21 天，经期 3 天。

**错误提示**：
- 日期格式不对：`日期格式错误，请使用 YYYY-MM-DD 格式，例如：2026-05-01`
- 周期太长或太短：`周期长度应在 21-35 天之间。`
- 经期太长或太短：`经期长度应在 2-10 天之间。`

**注意**：设置完成后，插件会**自动开启**当前会话的模拟。如果要暂停，使用 `/period toggle`。

---

### `/period toggle`

**权限**：仅管理员可用

**作用**：开启或暂停当前会话的身体感知。不影响周期参数，只是临时控制是否注入提示词。

**用法**：
```
/period toggle
```

**效果**：
- 如果当前是**开启**状态 → 变为**暂停**
- 如果当前是**暂停**状态 → 变为**开启**

每次切换后会回复当前状态：
```
生理周期模拟已开启。
```
或
```
生理周期模拟已暂停。
```

**注意**：如果当前会话**从未设置过周期参数**（即没执行过 `/period set`），会提示：
```
请先使用 `/period set <日期>` 设置周期参数。
```

---

### `/period advance <天数>`

**权限**：仅管理员可用

**作用**：快进时间。用于调试，可以快速体验 Bot 在不同阶段的表现，而不需要真的等好几天。

**参数说明**：

| 参数 | 必填 | 格式 | 默认值 | 说明 |
|------|------|------|--------|------|
| `<天数>` | 否 | 整数 | 1 | 快进多少天。正数向前，也可以填负数倒退。 |

**用法示例**：

```
/period advance
```
快进 1 天（省略参数时默认快进 1 天）。

```
/period advance 7
```
快进 7 天。

```
/period advance 14
```
快进 14 天，可以直接跳到下一个阶段体验。

**输出示例**：
```
时间已快进 7 天（累计快进 7 天）。
使用 `/period status` 查看当前状态。
```

**注意**：快进是**累加**的。如果上次快进了 3 天，这次再快进 5 天，总共就是 8 天。要归零需要 `/period reset`。

---

### `/period reset`

**权限**：仅管理员可用（需要 `ADMIN` 权限）

**作用**：清空当前会话的所有周期数据，恢复到未设置状态。

**用法**：
```
/period reset
```

**效果**：
- 删除该会话的经期首日、周期参数、快进天数等全部数据
- 清除该会话的静态锚点注入标记（下次对话会重新注入锚点）
- 清除注入计数器和冷启动计数器

**输出**：
```
当前会话的周期数据已重置。
```

**注意**：
- 这个操作**不可恢复**，请谨慎使用。
- 重置后，该会话的 Bot 会恢复到"无身体"状态，需要重新 `/period set` 才能再次启用。
- 其他会话的数据不受影响。

## 插件配置

在 AstrBot 的**插件管理 → Period → 配置**中，可以可视化编辑全部内容：

### 身体感知相关

| 设置项 | 说明 |
|--------|------|
| **静态锚点提示词** | 告诉 Bot"你拥有真实的身体，会经历自然的节律变化"。可完全自定义。 |
| **四阶段感受描述** | 月经期 / 卵泡期 / 排卵期 / 黄体期的主体感受 + 早/午/晚三个时段的微调。 |
| **禁用词库** | Bot 不会使用的词汇（如"月经"、"激素"等），防止出戏。 |

### 全局默认周期

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 全局默认经期首日 | 空 | 格式 `YYYY-MM-DD`。设置后所有未单独设置过周期的会话自动套用此默认值 |
| 全局默认周期长度 | 28 | 全局默认的完整周期天数 |
| 全局默认经期长度 | 5 | 全局默认的经期持续天数 |
| 对未设置会话自动启用 | 关 | 开启后，任何未被单独设置过周期的会话都会自动使用全局默认值启用生理周期 |

> **使用建议**：如果你希望 Bot 在所有群聊/私聊中默认都有生理状态，填写**全局默认经期首日**并开启**对未设置会话自动启用**。之后任何未单独设置过周期的对话都会自动生效，不需要再发 `/period set`。如果某个群需要特殊设置，再发 `/period set` 覆盖即可。

### 周期节律规则

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 经期持续天数 | 5 | 身体低潮期持续几天 |
| 排卵日 | 14 | 周期第几天进入感知最敏锐的阶段 |
| 排卵期窗口 | 3 | 感知敏锐阶段持续几天 |

### 对话注入策略

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 注入频率 | `every_request` | 每轮对话都告诉她身体状态 / 每 3 轮一次 / 仅被关心时 / 从不注入（仅保留指令查询） |
| 触发关键词 | `["怎么了", "还好吗"...]` | 仅在"被关心时"模式下生效 |
| 最大提示词长度 | 120 | 超限自动截断 |
| 叠加时段微调 | 开 | 根据当前时间（早晨/午后/深夜）追加额外描述 |
| 显示第几天 | 开 | 是否出现"第 X 天" |
| 包含阶段名 | 关 | 是否出现"月经期"等字样（**建议关闭，容易出戏**） |
| 冷启动轮数 | 0 | 新会话前 N 轮不注入身体状态，见下方详解 |

> **冷启动轮数详解**：这个设置控制 Bot 在**新会话**里聊了几轮之后才开始"有身体"。如果设为 `3`，那么该会话的前 3 轮对话插件不会注入任何身体状态提示词，Bot 表现为"无身体"状态；从第 4 轮起才正常按照**注入频率**策略工作。目的是防止 Bot 刚加群或刚被私聊时，第一句话就是"今天小腹有点沉"——这种出场方式太突兀。计数是**每个会话独立**的，A 群已经过了冷启动，B 群刚加进来仍然从头算起。保持 `0` 表示一进群就立即感知身体。

### 会话范围控制

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 全局注入模式 | 关 | 开启后所有会话都注入身体状态，不再管 UMO 列表 |
| UMO 列表模式 | 白名单 | `whitelist`：仅列表中的会话注入；`blacklist`：列表中的会话不注入 |
| UMO 会话列表 | 空 | 填入会话标识（如 `default:FriendMessage:123456`），精确控制哪些对话启用 |

> **使用建议**：如果你只想让 Bot 在特定群聊/私聊中表现出生理状态，关闭**全局注入模式**，把会话 UMO 填进列表，模式选**白名单**。如果你想让所有对话都生效，直接开启**全局注入模式**即可。

### 指令权限控制

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 指令权限控制 | `all` | `all` = 所有指令可用；`readonly` = 仅允许查看状态（关闭 set/toggle/advance/reset，防止 Bot 被玩坏）；`none` = 完全关闭所有指令回复 |

> **使用建议**：如果你担心 Bot 在群里被用户用 `/period advance` 等指令玩坏，把指令权限改为 `readonly`，用户只能查看状态，不能修改参数。如果想完全关闭指令回复，改为 `none`。

### 开关

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 全局总开关 | 开 | 关闭后 Bot 恢复为"无身体"状态，不再感知任何节律变化 |
| OOC 检测 | 开 | 检测到禁用词时记录日志 |
| 自动替换禁用词 | 关 | 将说漏嘴的词替换为 `**` |
| 调试模式 | 关 | 显示内部计算参数 |

## 她是如何"感知"到自己的身体的？

1. **身体认知的建立**：Bot 每进入一个**新会话**时，插件会在她的 system_prompt 里悄悄加一句话——"你拥有真实的身体，会经历自然的节律变化，但不要主动提及原因"。这句话只加一次，成为她人格的一部分。

2. **实时身体状态的传递**：每次对话时，插件会计算 Bot 今天处于周期的哪个阶段，然后把对应的**身体感受**（如"下腹有点坠胀，不太想动"）作为一条临时消息注入给 LLM。这条消息不会进入历史记录，用完即弃，不会污染她的记忆。

3. **人格自治**：LLM 收到"身体感受"后，会用 Bot 原有的人格去消化它。清冷人格和活泼人格面对同样的"疲倦"，反应天然不同——但都是真实的。

## 常见问题

**Q：Bot 会说"我月经来了"这种话吗？**  
A：默认不会。插件内置了 14 个禁用词，并在锚点中明确禁止 Bot 用医学术语分析自己。她只会自然感到"今天有点累"。如果偶尔说漏嘴，你可以在日志中看到 OOC 警告。

**Q：不同群的 Bot 会互相影响吗？**  
A：不会。每个群聊 / 私聊的身体数据完全独立，存储在 `data/plugin_data/astrbot_plugin_period/cycles.json` 中。

**Q：我只想在一个群里让 Bot 有生理状态，其他群保持正常，怎么做？**  
A：在插件配置中，关闭**全局注入模式**，把那个群的 UMO 标识填进**UMO 会话列表**，模式选**白名单**。这样只有这个群会注入身体状态，其他群不受影响。UMO 标识可以在 AstrBot 日志中看到，格式类似 `default:GroupMessage:123456`。

**Q：我想让 Bot 只在被关心时才表现出身体状态，平时正常说话。**  
A：把**注入频率**改为 `on_trigger`，保留触发关键词（如"怎么了"、"还好吗"）。平时她是正常的，只有用户关心她时，她才会带着当前的身体感受回复。

**Q：我想改成男性周期 / 仿生人周期 / 其他设定。**
A：直接修改**静态锚点提示词**和**四阶段感受描述**即可。把"女性身体"改成"仿生人机体"，把"下腹坠胀"改成"电量波动"——这个插件不限制你的设定方向，它只是提供了一个"身体感知"的框架。

**Q：设置全局默认值后，已经存在的群聊也会生效吗？**
A：会。全局默认值对**所有未单独设置过周期参数的会话**生效，不限于新群聊。只要某个群聊之前没执行过 `/period set`，它就会自动套用全局默认值。如果某个老群聊之前已经设置过了，则不受影响，仍然保持它自己的参数。

**Q：不同群可以设置不同的周期参数吗？**
A：完全可以。每个群聊 / 私聊的数据是独立的。你在 A 群执行 `/period set 2026-05-01 28 5`，在 B 群执行 `/period set 2026-03-15 30 6`，两个群的 Bot 会分别按照各自的参数计算身体状态，互不影响。

**Q：周期会自动循环吗，还是只运行一次？**
A：会自动无限循环。你只需要设置一次**经期首日**，引擎会根据这个锚点日期自动计算今天是周期第几天、处于哪个阶段。今天第 28 天，明天就是第 1 天，进入下一轮循环。

**Q：为什么 Bot 有时候不说身体状态？**
A：排查清单：① **全局总开关**是否开启；② 当前会话是否执行过 `/period set` 或配置了**全局默认值**；③ 当前会话是否被 `/period toggle` 暂停了；④ **冷启动轮数**是否还没聊够；⑤ **注入频率**是不是设成了 `on_trigger` 或 `interval_3`；⑥ 当前会话的 UMO 是否在**白名单**里（如果用了白名单模式）。

**Q：怎么查看当前会话的 UMO 标识？**
A：开启 AstrBot 的调试日志，在对话时搜索日志中的 `unified_msg_origin` 字段。群聊格式类似 `default:GroupMessage:123456`，私聊类似 `default:FriendMessage:123456`。把这个字符串填入**UMO 会话列表**即可精确控制。

**Q：指令权限改为 readonly 后，管理员也不能改设置了吗？**
A：是的。`readonly` 和 `none` 是在指令层面统一拦截的，不分用户身份。如果你需要临时调整某个群的参数，先把权限改回 `all`，执行完指令再改回去。

**Q：/period advance 快进时间会影响真实日期吗？**
A：不会。`advance` 只是一个**偏移量**，让引擎在计算时假装今天比实际日期过了几天，方便你调试不同阶段的表现。它不会修改系统时间，也不会改变锚点日期本身。要归零用 `/period reset`。

**Q：修改配置后需要重启 AstrBot 吗？**
A：不需要。在插件配置页保存后，下次对话立即生效。
